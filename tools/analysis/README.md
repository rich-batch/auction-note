# 사건 데이터 (`data/cases/<id>.json`)

물건 분석 글의 **사실 원본**. 사람이 서류를 보고 입력하고(`computed` 제외), Hugo 표·계산 도구·검사 스크립트·AI가 모두 이 파일을 읽는다.

- 후보 찾기(온비드, 등록은 안 함): `node tools/analysis/scan-onbid.mjs --date <YYYY-MM-DD>` (또는 `--days N`, 기본 7) — 아직 `data/cases`에 없는 물건 중 그 날짜(또는 기간)에 개찰하는 것만 나열
- 후보 찾기(법원경매, 등록은 안 함): `node tools/analysis/scan-court.mjs --court <법원코드> --date <YYYY-MM 또는 YYYY-MM-DD>` (법원코드 목록: `--courts`). `--court` 생략 시 `data/courts-of-interest.json`의 `courts` 배열에 등록한 관심 법원을 순서대로 조회(세션 공유 + 법원 전환마다 1분 지연으로 한 번에 여러 법원을 안전하게 훑음, 차단/호출 한도 도달 시 그 자리에서 멈추고 다음 실행에서 이어감)
- 후보 찾기(공매+경매 한 번에, 등록은 안 함): `node tools/analysis/scan-daily.mjs --date <YYYY-MM-DD>` — 위 두 스캔을 같은 날짜로 그대로 실행
- 두 스캔 모두 기본으로 분석 가치가 낮은 물건(최저가 300만원 미만, 공유지분 매각)은 생략한다(`tools/lib/candidate-filter.mjs`) — 등기부만으로 하는 이 저장소의 권리분석이 잘 안 먹히거나(공유지분) 감정가 자체가 콘텐츠가 되기 어려운(자투리 저가) 구간이라서다. `--min-price <원>` `--min-price=0`(생략 없이) `--include-share`로 조정
- 새 파일(직접 입력): `node tools/analysis/new-case.mjs <id> <사건번호> <분류>`
- 새 파일(온비드, 자동 조회): `node tools/analysis/fetch-onbid.mjs <물건관리번호> [--type=trust]` — 최초 1회 `npx playwright install chromium` 필요. `--type=trust` 없으면 온비드 표시를 그대로 받아들이고(압류재산·국유재산·공유재산·기타일반재산), 있으면 신탁공매(신탁법 제4조·제22조)로 취급. **압류재산·부동산(아파트·빌라·상가·토지)은 `rights[]`·`tenants[]`도 자동으로 채운다** — 온비드 물건 상세 페이지가 로그인 없이 공개하는 "등기사항증명서 주요정보"·"임대차 정보"·"점유관계"·"배분요구현황" 표를 그대로 읽는다(`tools/lib/onbid.mjs`). 등기사항전부증명서 원본이 아니라 온비드가 옮긴 요약이라 애매한 항목(권리종류 불명, 배당요구 미공개 등)은 `special[]`에 검토로 남는다 — 입찰 전 최종 대조 권장. 신탁공매·국유재산·공유재산·기타일반재산·자동차는 이 자동 채움 대상이 아니다(계산 성격이 달라 사람이 채움)
- 새 파일(법원경매, 자동 조회): `node tools/analysis/fetch-court.mjs <법원코드> <사건번호> --sale-date <YYYY-MM-DD>` — `court-auction-notice-search` 패키지(안티봇 가드 내장) 사용. 감정가·최저가·물건종류·소재지·배당요구종기·청구금액까지 자동 입력, 매각물건명세서·등기·현황조사서는 여전히 사람이 채움
- 첨부서류 추가 확인(법원경매, 기존 파일에): `node tools/analysis/fetch-court-docs.mjs <id>` — 법원경매정보가 캡차·로그인 없이 공개하는 **현황조사서**를 직접 호출해(`court-auction-notice-search`가 다루지 않는 엔드포인트, `tools/lib/court-docs.mjs`) `tenants[]`(점유관계·전입일)를 자동으로 채운다. **점유자 실명은 이 API가 마스킹 없이 그대로 주지만 이 스크립트는 절대 저장하지 않는다** — 구조화된 사실만 뽑고 이름·서술형 텍스트는 버린다. `tenants[]`가 이미 있으면 덮어쓰지 않고 참고용으로만 출력. 같이 조회하는 "물건상세"의 최선순위 설정(말소기준권리 후보)은 rights[]와 대조할 참고용으로 콘솔에만 보여준다(case 파일에 쓰지 않음 — `computed`는 여전히 `compute.mjs`가 rights[] 입력만 보고 계산). **감정평가서**는 법원경매정보가 PDF로만 제공하고 무단 복제·링크 금지 경고가 붙어 있어 내용을 옮기지 않는다(감정가 숫자는 이미 `fetch-court.mjs`가 채움). 같은 물건상세 응답의 `csPicLst`/`picDvsIndvdCnt`로 **첨부 사진**의 존재·개수(유형 코드별)도 자동으로 파악해 `source.documents`에 "사진"을 추가한다 — 원본 이미지(base64)는 같은 저작권 정책 때문에 절대 저장하지 않고 개수만 콘솔·case 파일에 남긴다. **매각물건명세서·등기사항전부증명서**는 자동 확인 경로를 못 찾음(등기 열람은 인터넷등기소 연계 유료서비스로 확인됨) — 계속 사람이 직접 확인
- 시세 후보 찾기(사람이 확인 후 market.trades에 반영): `node tools/analysis/fetch-market.mjs <id> [--months N]` — 국토교통부 실거래가. 1차로 k-skill-proxy(API 키 불필요, apartment·villa·commercial)를 시도하고, 실패하면 apartment에 한해 국토교통부 실거래가공개시스템(rt.molit.go.kr)에서 Playwright로 직접 엑셀을 내려받아 대체한다(k-skill-proxy 자체 이슈 NomaDamas/k-skill#569 — 이 프록시 라우트가 상시 간헐적으로 502를 반환하는 것으로 기록됨). villa·commercial은 프록시가 안 되면 현재 대체 경로가 없다
- 계산: `node tools/analysis/compute.mjs <id>` (검증 실패 시 무엇이 틀렸는지 알려 줌)
- 단계 확인: `node tools/analysis/status.mjs`
- 엔진 테스트: `node --test tools/analysis/rights.test.mjs`

**저장소와 사이트는 공개 상태다.** 이름·주민번호·전화번호는 넣지 않는다(검증이 막는다). 서류 원본(PDF·캡처)은 저장소 밖이나 gitignore된 `private/`에 둔다. 소재지(`case.region`)는 전체 주소(지번·동/호수 포함)를 넣는다 — 법원경매정보·온비드가 법률상 공개하는 정보다.

## ID

court: `<법원>-<연도>ta<번호>[-<물건번호>]` — 예: `seoul-central-2026ta12345`, 물건번호 2번이면 `seoul-central-2026ta12345-2` (`fetch-court.mjs`가 자동으로 이 규칙대로 만든다 — 법원 slug 매핑은 `tools/lib/courts.mjs`).
onbid: `onbid-<물건관리번호에서 하이픈만 뺀 숫자>` — 예: 물건관리번호 `2022-0200-007090`이면 `onbid-20220200007090` (`fetch-onbid.mjs`가 자동으로 이 규칙대로 만든다).
이 ID가 파일 이름, 글 폴더(`content/analysis/<id>/`), 주소(`/analysis/<id>/`)를 겸한다. 발행 후 바꾸지 않는다.

`computed.input_hash`는 입력(`case`·`sale`·`rights`·`tenants`·`special`·`spec_sheet`·`market`)의 해시다. 입력을 고치면 달라져서 검사가 "다시 계산하라"고 알려 준다. `market`은 시세갭·확인 지표 점수 계산에 쓰이므로 해시에 포함된다. `result`(매각 결과)는 어떤 계산에도 쓰이지 않아 해시에서 빠진다.

## 자동차(`case.category: "car"`) — 부동산과 다른 점

법적 근거: 국세징수법 제92조제1항("공매재산에 설정된 모든 질권·저당권 및 가등기담보권은 매각으로 소멸된다")은 순서를 따지지 않는다. court 경매도 같다 — 민사집행규칙 제108조가 자동차집행에 부동산 강제경매 규정을 그대로 따르게 하면서 "등기"를 "등록"으로 볼 뿐이라 민사집행법 제91조제2항(모든 저당권 소멸)이 동일하게 적용된다.

- **등록된 저당권·압류 등은 순서와 무관하게 항상 소멸한다.** 부동산의 "말소기준권리보다 앞서면 인수" 규칙 자체가 적용되지 않는다 — `computed.base_right`는 항상 `null`.
- **`tenants`는 항상 빈 배열이어야 한다**(검증이 막음). 자동차엔 주택임대차보호법·상가건물임대차보호법이 적용될 대상(임차권)이 없다. 리스·할부 소유권유보 같은 점유·소유 문제는 `special`에 적는다.
- **유일한 인수 위험은 유치권**이다(매수인이 유치권으로 담보된 채권을 변제할 책임, 국세징수법 제92조제4항·민사집행법 제91조제5항). 유치권은 자동차등록원부에 나타나지 않는 점유·채권 관계라 코드가 판정하지 않고 항상 review로 남긴다 — 점유자·정비 이력을 확인해 `special`에 적는다.
- 입력 서류는 등기사항전부증명서가 아니라 **자동차등록원부**(을구의 저당권 등록사항). `fetch-onbid.mjs`가 물건종류를 "자동차"로 인식하면 이 서류를 안내한다.
- 온비드 압류재산 자동차는 `fetch-onbid.mjs <물건관리번호>`로 공개 필드(소재지=현재 보관 장소, 감정가·최저가·입찰기간)까지는 자동으로 채워진다.

## 국유재산·공유재산(`case.onbid_property_type`) — 부동산 압류재산과 다른 점

법적 근거: 국유재산법 제11조·공유재산법 제8조(사권설정 재산의 취득 제한) — "사권(私權)이 설정된 재산은 그 사권이 소멸되기 전에는 국유(공유)재산으로 취득하지 못한다"(판결에 의한 취득은 예외). 즉 매각 시점에 저당권 등 등기된 담보물권이 원칙적으로 없다 — court 경매·압류재산 공매처럼 "말소기준권리보다 앞선 권리를 인수"하는 문제 자체가 생기지 않는다.

- **`rights[]`는 빈 배열([])인 게 정상이다.** 값이 있으면 판결에 의한 취득 등 이례적인 경우라 전부 review로 남긴다(등기 자체를 소멸/인수로 판정하지 않음) — `computed.base_right`는 항상 `null`.
- **`tenants`는 항상 빈 배열이어야 한다**(검증이 막음). 사용허가·대부(임대) 계약 중인 점유자가 있을 수 있지만, 매각으로 그 계약이 어떻게 되는지는 계약 조건과 관련 조문(국유재산법 제34조·제36조, 공유재산법 제31조·제35조)을 같이 봐야 하는 사실 문제라 코드가 판정하지 않는다 — `special`에 적는다.
- 입력 서류는 등기사항전부증명서가 아니라 **공고문·사용허가·대부계약 현황**. `fetch-onbid.mjs`가 이 유형을 인식하면 이 서류를 안내한다.
- `fetch-onbid.mjs <물건관리번호>`가 온비드의 "재산유형" 표시(국유재산/공유재산)를 그대로 받아들여 사건 파일을 만든다 — `--type` 옵션이 필요 없다.

## 기타일반재산(`case.onbid_property_type`) — 전부 검토로 남기는 최소 계산

온비드 "기타일반재산"은 위임기관(수탁회사·파산관재인·기업회생지원처 등)마다 매각 근거 법령 자체가 다르다(예: 회생지원 목적의 수탁재산 매각, 채무자의 지식재산권 매각위임). 하나의 계산으로 일반화할 근거가 없어 등기 권리·점유 관계를 전부 review로 남기는 최소 계산만 한다 — `tenants`는 항상 빈 배열(검증이 막음), `rights[]`는 값이 있어도 없어도 되며 있으면 전부 "검토"로 표시된다.

실제로는 압류재산·신탁공매·국유재산·공유재산에 해당하는데 온비드 표시만 "기타일반재산"인 경우가 있다(위임기관 이름으로 짐작 가능) — 신탁공매면 `--type=trust`로 재분류한다.

## 온비드 압류재산 — 정보 확보 체크리스트

`fetch-onbid.mjs`가 자동으로 채우는 것과, 사람이 나중에 채워야 하는 것을 시점별로 나눈다. 항목마다 "언제 확인 가능한가"가 다르므로 이 순서로 점검한다.

**A. 물건 상세 페이지에서 즉시 확인 가능 (무료, 로그인 불필요, `fetch-onbid.mjs`가 자동 입력)**
- 물건관리번호, 재산유형(압류재산인지), 공고기관, 소재지(전체 주소), 물건종류, 면적
- 감정평가금액, 회차별 공매예정가격, 입찰기간, 개찰일시, 유찰횟수, 입찰보증금율(통상 10%)
- 등기사항증명서 주요정보(권리종류·권리자 유형·설정일자·설정금액) — **공매대행 의뢰 시점 기준 요약**이라 참고용. 접수번호가 없고 등기부 순위번호와 무관하다고 온비드가 명시
- 임대차 정보(임차인 보증금·확정일·전입일) — 감정평가서·배분요구서 기준
- 정정내역(유의사항) — 대지권미등기 등 특이사항이 있으면 여기 나옴

**B. 입찰 시작 7일 전부터만 확인 가능 (국세징수법 제77조제2항 — 법정 시한, 더 일찍 볼 방법 없음)**
- 공매재산명세서: **임차인의 배당(배분)요구 여부**와 그 일자. `tenants[].dividend_claim`은 이게 없으면 확정할 수 없다 — 지어내지 말고 이 시점까지 기다린다.

**C. 사람이 직접 서류·현장으로 확인해야 하는 것**
- 최신 등기사항전부증명서(온비드 요약은 참고용, 입찰 전 재확인 필수 — 인터넷등기소, 소액 유료)
- 실제 점유 현황(현장 방문), 관리비 체납 여부(관리사무소)

**D. `compute.mjs`가 계산하는 것**
- 말소기준권리, 등기 인수/소멸, 임차인 대항력, 인수 예상액, 확인 지표 점수, 시세갭(시세를 넣었을 때만)
